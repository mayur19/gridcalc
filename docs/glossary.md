# Glossary

Domain terms used across gridcalc code and documentation. Where a term maps to code, the file is named. Terms marked _(planned)_ describe features that are not implemented yet; see [planning/backlog.md](planning/backlog.md).

## Cells, references and ranges

| Term                                               | Definition                                                                                                                                                                                                                                                          |
| -------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **A1 reference**                                   | A cell address written as column letters followed by a 1-based row number, e.g. `B7`. Columns run `A` to `XFD` (16,384) and rows 1 to 1,048,576. Internally rows and columns are 0-based (`row_idx`, `col_idx`). See `packages/shared/src/formula/references.ts`.   |
| **Absolute reference**                             | A reference with a `$` before the column, the row or both (`$A$1`, `A$1`, `$A1`). The `$` marks the part that must not shift when a formula is copied, filled or moved. gridcalc parses and preserves the markers today; copy/paste adjustment arrives with GC-071. |
| **Relative reference**                             | A reference without `$` markers. On copy, paste or fill _(planned, GC-071, GC-073)_ it shifts by the same offset as the formula cell.                                                                                                                               |
| **Mixed reference**                                | A reference absolute in one dimension only, e.g. `$A1` (column fixed) or `A$1` (row fixed).                                                                                                                                                                         |
| **Sheet-qualified reference**                      | A reference prefixed by a sheet name and `!`, e.g. `Data!B2`. Names containing spaces or punctuation are quoted with single quotes: `'My Sheet'!C4`.                                                                                                                |
| **Range**                                          | A rectangular block of cells written `top-left:bottom-right`, e.g. `A1:C10`. The `:` operator has the highest binding power in the parser (80).                                                                                                                     |
| **Wide range**                                     | A range spanning more than 64 columns (`WIDE_RANGE_COLUMNS`). Wide ranges are kept in a separate list instead of column buckets in the range index.                                                                                                                 |
| **Whole-row / whole-column reference** _(planned)_ | References such as `A:A` or `1:1` covering an entire column or row (GC-029).                                                                                                                                                                                        |
| **3D reference** _(planned)_                       | A reference spanning the same cells across consecutive sheets, e.g. `Sheet1:Sheet3!A1` (GC-029).                                                                                                                                                                    |
| **Named range** _(planned)_                        | A user-defined name such as `Revenue` that refers to a range, with workbook or sheet scope (GC-028). Unknown names evaluate to `#NAME?`.                                                                                                                            |
| **Sparse cell storage**                            | Only non-empty cells have a row in the `cells` table, keyed by `(sheet_id, row_idx, col_idx)`. Clearing a cell deletes its row.                                                                                                                                     |
| **Raw input**                                      | Exactly what the user typed into a cell (`raw` column, at most 8,192 characters), as opposed to its computed value.                                                                                                                                                 |
| **Computed value**                                 | The last evaluated result of a cell (`value_type`, `value` columns), stored so reads never need the engine.                                                                                                                                                         |
| **Cell window**                                    | The rectangular range a client requests with `GET .../cells?range=A1:Z100`, limited to 250,000 cells.                                                                                                                                                               |

## Formula language

| Term                              | Definition                                                                                                                                                                                                                                             |
| --------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **Formula**                       | Cell input that starts with `=`; the rest is parsed as an expression.                                                                                                                                                                                  |
| **Token**                         | A lexical unit produced by the tokenizer: number, string, boolean, error literal, cell reference, function name, name, operator or punctuation. See `tokenizer.ts`.                                                                                    |
| **AST (abstract syntax tree)**    | The immutable tree the parser produces from tokens; evaluated by `evaluator.ts` and printed by `printer.ts`.                                                                                                                                           |
| **Pratt parser**                  | A top-down operator-precedence parser in which each operator has a binding power. gridcalc's powers: comparison 10, `&` 20, `+ -` 30, `* /` 40, `^` 50 (left-associative), postfix `%` 60, unary 70, range `:` 80.                                     |
| **Precedence**                    | The order in which operators bind. Because unary minus binds tighter than `^`, `=-2^2` evaluates to 4, matching mainstream spreadsheets.                                                                                                               |
| **Missing argument**              | An argument left empty between commas, e.g. `IF(A1,,1)`. It is passed to the function as an explicit empty value.                                                                                                                                      |
| **Normalized formula**            | The canonical text produced by printing a parsed formula: upper-case functions and references, consistent spacing, necessary parentheses only. Returned by `POST /api/v1/formulas/parse`.                                                              |
| **Coercion**                      | Implicit conversion between number, text and boolean during evaluation (`coercion.ts`): `"3"+1` = 4, `TRUE+1` = 2, empty = 0 or `""`, non-numeric text in arithmetic = `#VALUE!`.                                                                      |
| **Scalar**                        | A single value: number, string, boolean, empty or error. Ranges are evaluated to grids of scalars.                                                                                                                                                     |
| **Error value**                   | A first-class value representing failure: `#DIV/0!`, `#VALUE!`, `#REF!`, `#NAME?`, `#N/A`, `#NUM!`, `#NULL!`, plus gridcalc's `#CYCLE!` (circular reference) and `#ERROR!` (unparseable input). Errors propagate through operators and most functions. |
| **Error propagation**             | The rule that an operation receiving an error returns that error, unless the function intercepts errors (IFERROR, ISERROR, ISNA).                                                                                                                      |
| **Criteria**                      | The condition string in SUMIF/COUNTIF, optionally prefixed by `=`, `<>`, `<`, `<=`, `>`, `>=`, with wildcards `*` (any run), `?` (one character) and `~` (escape). Matching is case-insensitive. See `functions/criteria.ts`.                          |
| **Approximate match**             | Lookup mode (MATCH type 1, VLOOKUP/HLOOKUP with `TRUE`) that returns the largest value less than or equal to the key in sorted data, found by binary search.                                                                                           |
| **General format**                | Default number display: up to 15 significant digits, switching to exponent notation for very large or small magnitudes (`formatGeneral`).                                                                                                              |
| **Significant digits (15)**       | gridcalc rounds displayed numbers and subtraction results to 15 significant digits so that `0.3-0.1` shows `0.2` despite IEEE 754 binary representation.                                                                                               |
| **Function catalog**              | The registry of supported functions with their signatures (`functions/registry.ts`), served by `GET /api/v1/formulas/functions`. 43 functions today.                                                                                                   |
| **Volatile function** _(planned)_ | A function whose result can change without any precedent changing, such as TODAY, NOW and RAND. Volatile cells are recalculated on every commit (GC-033).                                                                                              |
| **Dynamic reference** _(planned)_ | A reference computed at evaluation time, by INDIRECT or OFFSET, so precedents cannot be known statically (GC-033).                                                                                                                                     |
| **Spill** _(planned)_             | Writing an array result from one formula into neighbouring cells (the spill range). If any target cell is occupied, the anchor shows `#SPILL!` (GC-034).                                                                                               |
| **Serial date** _(planned)_       | A date stored as a number of days since the spreadsheet epoch, so dates can be added and compared like numbers (GC-024).                                                                                                                               |
| **Number format** _(planned)_     | A display code such as `#,##0.00`, `0%` or `yyyy-mm-dd` applied to a value without changing it (GC-065).                                                                                                                                               |

## Recalculation

| Term                                   | Definition                                                                                                                                                                                                                                              |
| -------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Precedent**                          | A cell or range a formula reads. In `C1 = A1 + SUM(B1:B5)`, the precedents of C1 are A1 and B1:B5.                                                                                                                                                      |
| **Dependent**                          | A formula that reads a given cell. C1 above is a dependent of A1. Dependents can be direct or transitive.                                                                                                                                               |
| **Static conservative precedents**     | gridcalc derives precedents from the formula text without evaluating it, and includes every branch of IF and CHOOSE. This can over-approximate but never misses a dependency (`dependencies.ts`, ADR 0011).                                             |
| **Dependency graph**                   | The directed graph of precedent-to-dependent edges, holding cell edges plus a range index (`graph/dependency-graph.ts`).                                                                                                                                |
| **Range index**                        | A structure that finds formulas whose range precedents contain a given cell. gridcalc buckets ranges by column, with a separate list for wide ranges (`graph/range-index.ts`). A 2D interval tree is planned (GC-047).                                  |
| **Dirty set**                          | The cells that must be re-evaluated after an edit: the edited formulas plus the transitive closure of their dependents, collected by breadth-first search (`collectDirty`).                                                                             |
| **Incremental recalculation**          | Re-evaluating only the dirty set, as opposed to a full recalculation of every formula.                                                                                                                                                                  |
| **Full recalculation**                 | Evaluating every formula in the workbook from scratch, as done by `RecalcEngine.create`. Used as the oracle in equivalence tests.                                                                                                                       |
| **Topological order**                  | An order in which every cell is evaluated after all its precedents.                                                                                                                                                                                     |
| **SCC (strongly connected component)** | A maximal set of cells in which each cell can reach every other through dependency edges. An SCC with more than one cell, or a single cell with a self-loop, is a cycle.                                                                                |
| **Tarjan's algorithm**                 | Linear-time algorithm for finding SCCs. gridcalc runs an iterative (non-recursive) version over the dirty subgraph, then reverses the output to get evaluation order (`planRecalc`). This lets a 100,000-long chain recalculate without stack overflow. |
| **Cycle (circular reference)**         | Cells that depend on themselves directly or indirectly. Every member of a cyclic SCC evaluates to `#CYCLE!` until the cycle is broken.                                                                                                                  |
| **Iterative calculation** _(planned)_  | Opt-in mode that resolves intentional cycles by repeated evaluation up to a maximum iteration count or tolerance (GC-048).                                                                                                                              |
| **Deferred sheet binding**             | A formula naming a sheet that does not exist yet waits on that name; when the sheet is added, the formula is re-bound and recalculated (`RecalcEngine.addSheet`, ADR 0013).                                                                             |
| **Changed cells**                      | The cells returned by a PATCH: every edited cell plus every recalculated cell whose value actually changed.                                                                                                                                             |
| **Engine cache**                       | An in-process LRU of `RecalcEngine` instances keyed by workbook id, valid only for the exact revision it was built at (`engine-cache.ts`, `ENGINE_CACHE_SIZE`, ADR 0008).                                                                               |
| **Single-writer engine**               | The engine mutates its internal state only from one caller at a time (guaranteed by the workbook row lock) and exposes frozen, immutable outputs (ADR 0006).                                                                                            |

## Persistence and concurrency

| Term                                   | Definition                                                                                                                                                                          |
| -------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Workbook**                           | A document containing ordered sheets, owned by one organization. Has a monotonic `revision`.                                                                                        |
| **Sheet**                              | A grid inside a workbook, referenced by id internally and by a case-insensitively unique name in formulas. Defaults to 100,000 rows by 52 columns.                                  |
| **Revision**                           | A monotonically increasing integer on the workbook row, incremented by every committed change. Clients send it as `baseRevision`.                                                   |
| **Revision log**                       | The append-only `workbook_revisions` table with one row per committed change (actor, kind, edit count, recalculated count). Basis for version history _(planned, GC-094)_.          |
| **Optimistic concurrency**             | Writers state the revision they based their edit on; the server rejects the write with 409 `REVISION_CONFLICT` (and `details.currentRevision`) if the workbook moved on (ADR 0007). |
| **Row lock**                           | `SELECT ... FOR UPDATE` on the workbook row at the start of each write transaction, serializing writers to one workbook.                                                            |
| **Edit batch**                         | Up to 1,000 cell edits `{sheetId, row, col, raw}` submitted in one PATCH and committed atomically.                                                                                  |
| **Revision vector** _(planned)_        | Per-cell revision metadata used by real-time collaboration to resolve concurrent edits with last-writer-wins (GC-089, ADR 0017).                                                    |
| **Last-writer-wins (LWW)** _(planned)_ | Conflict rule in which the later committed edit to the same cell prevails and the earlier writer is notified.                                                                       |
| **Migration**                          | A forward-only plain SQL file in `apps/api/migrations`, applied once in its own transaction under an advisory lock, with a checksum that detects later edits (ADR 0004).            |

## Identity, tenancy and operations

| Term                         | Definition                                                                                                                                                                       |
| ---------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Organization (tenant)**    | The unit of data isolation. Every workbook belongs to exactly one organization, and repositories filter by organization id (ADR 0005).                                           |
| **Membership**               | A user's role within an organization.                                                                                                                                            |
| **Role**                     | One of owner, admin, editor, viewer, mapped to permissions in `modules/rbac/permissions.ts`.                                                                                     |
| **Permission**               | A capability such as `workbook:read`, `workbook:write`, `member:manage`, `audit:read` or `org:manage`.                                                                           |
| **Workbook ACL** _(planned)_ | Per-workbook roles (owner, editor, commenter, viewer) that override the organization role (GC-098).                                                                              |
| **Session**                  | Server-side login state. The browser holds an opaque token in the HttpOnly `gc_session` cookie; the database stores only HMAC-SHA256(`SESSION_SECRET`, token) (ADR 0014).        |
| **CSRF double-submit**       | Defence in which a per-session token is mirrored in the readable `gc_csrf` cookie and must be echoed in the `x-csrf-token` header on mutating requests.                          |
| **Origin allow-list**        | Mutating requests must carry an `Origin` matching `APP_ORIGIN`.                                                                                                                  |
| **Login throttle**           | In-memory limits on login attempts: per IP window, distinct emails per IP, and per-email progressive backoff (30 s doubling to 1 h). Moves to PostgreSQL with GC-008 (ADR 0015). |
| **TRUST_PROXY**              | Configuration stating which proxies may set `X-Forwarded-For`: `false`, a hop count, or a list of proxy IPs/CIDRs. Never `true`; must be explicit in production.                 |
| **Audit event**              | An append-only row in `audit_events` recording who did what to which target, with the request id.                                                                                |
| **Outbox** _(planned)_       | A local table where outbound messages (verification, invitation, password reset) are written instead of calling a mail service (GC-009, GC-016, GC-018).                         |
| **Envelope**                 | The response shape `{data, error}` used by every endpoint; errors carry a stable `code`, a message and optional `details`.                                                       |
| **Pending endpoint**         | A routed API operation that answers `501 NOT_IMPLEMENTED` with its ticket id in `error.details.ticket`.                                                                          |
| **Liveness / readiness**     | Health probes: liveness reports the process is up; readiness also checks PostgreSQL and returns 503 when it is unreachable.                                                      |
| **Virtualized grid**         | A grid that renders only the cells inside the viewport (plus a small margin), absolutely positioned, so DOM size does not grow with sheet size (ADR 0016).                       |
