# gridcalc Requirements

This document lists the functional (FR) and non-functional (NFR) requirements of gridcalc. Each requirement has a MoSCoW priority (Must, Should, Could, Won't-now), a status that matches the code and [the backlog](../planning/backlog.md), the related ticket(s), and acceptance criteria that a test can check.

- **Implemented**: merged, covered by tests in `packages/shared/test`, `apps/api/test` or `apps/web/test`.
- **Pending**: not built. If the requirement has an API operation, that operation is routed today and answers `501 NOT_IMPLEMENTED` with the ticket in `error.details.ticket` (see `apps/api/src/modules/pending/pending.routes.ts`).

Traceability to modules and tests is in [requirements-traceability.md](requirements-traceability.md). Terms are defined in [../glossary.md](../glossary.md).

Summary: 126 functional requirements (FR-001 to FR-050 Implemented, FR-051 to FR-126 Pending) and 29 non-functional requirements.

## 1. Functional requirements

### 1.1 Formula language (implemented)

| ID     | Requirement                                                                                                                                                              | Priority | Status      | Tickets        | Acceptance criteria                                                                                                                                                                                                                                                                                    |
| ------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | -------- | ----------- | -------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| FR-001 | The system shall tokenize formulas into numbers, strings, booleans, error literals, cell references, function names, names and operators.                                | Must     | Implemented | GC-020         | Numbers accept `1`, `1.`, `.5`, `1e3`, `2.5E-2`; strings use `""` as an escaped quote (`"a""b"` yields `a"b`); `TRUE`/`FALSE` are booleans; `#DIV/0!`, `#N/A` and the other error codes lex as error literals; `<=`, `>=`, `<>` lex greedily as one operator; every token records its source position. |
| FR-002 | The system shall support A1 references with optional `$` absolute markers and optional sheet prefixes, including quoted sheet names.                                     | Must     | Implemented | GC-020, GC-021 | `A1`, `$A$1`, `A$1`, `$A1`, `Sheet2!B3` and `'My Sheet'!C4` parse as references; references beyond 1,048,576 rows or 16,384 columns (`XFE1`) are treated as names, not cells; function names and references are upper-cased.                                                                           |
| FR-003 | The parser shall apply spreadsheet operator precedence: comparison < `&` < `+ -` < `* /` < `^` (left-associative) < postfix `%` < unary minus/plus < range `:`.          | Must     | Implemented | GC-021         | `=-2^2` evaluates to 4; `=2^3^2` evaluates to 64; `=1+2&"x"` yields `3x`; `=50%*2` yields 1; a multi-cell range used as a single value (`=A1:B2`) yields `#VALUE!`.                                                                                                                                    |
| FR-004 | The parser shall reject hostile or malformed formulas with bounded resources.                                                                                            | Must     | Implemented | GC-020, GC-021 | Formulas over 8,192 characters, nesting over 64 levels or more than 255 arguments raise a syntax error with a position; missing arguments (`=IF(A1,,2)`) are accepted as explicit empty arguments.                                                                                                     |
| FR-005 | The system shall print an AST back to a canonical formula string.                                                                                                        | Must     | Implemented | GC-021         | For every parser test formula, `parse(print(parse(f)))` equals `parse(f)`; printing normalizes case and spacing and keeps needed parentheses only.                                                                                                                                                     |
| FR-006 | The system shall classify raw cell input as empty, formula, text, number, boolean or error.                                                                              | Must     | Implemented | GC-022         | `''` clears the cell; input starting with `=` is a formula; a leading apostrophe forces text and is not displayed; `5%` stores 0.05; `true` stores boolean TRUE; `#N/A` stores the error; an invalid formula stores `#ERROR!` with the parser message and a 0-based offset that counts the `=`.        |
| FR-007 | The evaluator shall coerce values between number, text and boolean following spreadsheet rules.                                                                          | Must     | Implemented | GC-022         | `="3"+1` = 4; `="abc"+1` = `#VALUE!`; `=TRUE+1` = 2; empty cells are 0 in arithmetic and `""` in text context; numeric text with `%` (`"5%"`) coerces to 0.05.                                                                                                                                         |
| FR-008 | Comparison operators shall order numbers < text < booleans and compare text case-insensitively.                                                                          | Must     | Implemented | GC-022         | `=1<"a"` is TRUE; `="a"<TRUE` is TRUE; `="ABC"="abc"` is TRUE.                                                                                                                                                                                                                                         |
| FR-009 | Error values shall propagate through operators and functions; the error set is `#DIV/0!`, `#VALUE!`, `#REF!`, `#NAME?`, `#N/A`, `#NUM!`, `#NULL!`, `#CYCLE!`, `#ERROR!`. | Must     | Implemented | GC-022         | `=1/0` = `#DIV/0!`; `=UNKNOWNFN(1)` = `#NAME?`; `=1+#N/A` = `#N/A`; the leftmost error wins in binary operators; IFERROR and ISERROR intercept errors.                                                                                                                                                 |
| FR-010 | The evaluator shall evaluate ranges, passing bare cell references to functions as 1x1 ranges, and cap range size.                                                        | Must     | Implemented | GC-022         | `=SUM(A1:B2)` sums four cells; `=SUM(A1)` treats `A1` as a range (text ignored); a range larger than 2,000,000 cells yields `#NUM!` with an explanatory message.                                                                                                                                       |
| FR-011 | Numbers shall be displayed in General format with up to 15 significant digits, and subtraction results shall be rounded to 15 significant digits.                        | Must     | Implemented | GC-022         | `=0.3-0.1` displays `0.2`; `=1/3` displays `0.333333333333333`; very large and very small numbers switch to exponent notation.                                                                                                                                                                         |
| FR-012 | The function library shall include math functions SUM, PRODUCT, MOD, POWER, PI, SUMIF, ABS, INT, SQRT, ROUND, ROUNDUP, ROUNDDOWN.                                        | Must     | Implemented | GC-023         | `=MOD(-3,2)` = 1 (sign of divisor); `=SQRT(-1)` = `#NUM!`; `=ROUND(2.5,0)` = 3; `=ROUNDDOWN(-2.5,0)` = -2; `=INT(-2.5)` = -3.                                                                                                                                                                          |
| FR-013 | The function library shall include statistical and counting functions AVERAGE, MIN, MAX, COUNT, COUNTA, COUNTBLANK, COUNTIF.                                             | Must     | Implemented | GC-023         | `=AVERAGE` of an all-text range = `#DIV/0!`; COUNT counts numbers only; COUNTA counts non-empty cells; COUNTBLANK counts empty cells and empty strings.                                                                                                                                                |
| FR-014 | The function library shall include logical and information functions IF, IFERROR, AND, OR, NOT, ISBLANK, ISNUMBER, ISTEXT, ISERROR, ISNA.                                | Must     | Implemented | GC-023         | IF and CHOOSE evaluate only the selected branch (`=CHOOSE(2,1/0,"two")` = `two`); `=IF(FALSE,1)` returns FALSE; AND over a range with no logical values = `#VALUE!`; ISNA is TRUE only for `#N/A`.                                                                                                     |
| FR-015 | The function library shall include text functions CONCAT, CONCATENATE, LEFT, RIGHT, MID, LEN, UPPER, LOWER, TRIM.                                                        | Must     | Implemented | GC-023         | `=TRIM("  a   b ")` = `a b`; `=MID("abc",0,1)` = `#VALUE!`; `=LEFT("abc")` = `a`; CONCAT flattens ranges.                                                                                                                                                                                              |
| FR-016 | The function library shall include lookup functions MATCH, VLOOKUP, HLOOKUP, INDEX, CHOOSE, with approximate match via binary search.                                    | Must     | Implemented | GC-023         | Exact VLOOKUP miss = `#N/A`; approximate MATCH on sorted data returns the largest value <= the key; INDEX out of bounds = `#REF!`; CHOOSE with index 0 = `#VALUE!`.                                                                                                                                    |
| FR-017 | Criteria arguments (SUMIF, COUNTIF) shall support comparison prefixes and wildcards `*`, `?` with `~` escape.                                                            | Must     | Implemented | GC-023         | `=COUNTIF(A1:A5,">=3")` counts numbers >= 3; `"a*"` matches `apple`; `"~*"` matches a literal asterisk; matching is case-insensitive.                                                                                                                                                                  |

### 1.2 Recalculation (implemented)

| ID     | Requirement                                                                                                                                                         | Priority | Status      | Tickets        | Acceptance criteria                                                                                                                                                                  |
| ------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------- | ----------- | -------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| FR-018 | The engine shall derive static, conservative precedents for each formula, including every branch of IF and CHOOSE.                                                  | Must     | Implemented | GC-030         | `=IF(A1,B1,C1)` has precedents A1, B1 and C1 regardless of A1's value; range arguments register a range edge.                                                                        |
| FR-019 | The dependency graph shall index range precedents in column buckets, sending ranges wider than 64 columns to a separate wide list.                                  | Must     | Implemented | GC-030         | A change to `C5` finds dependents of `A1:D10`; a range of 65+ columns is stored in the wide list and still found.                                                                    |
| FR-020 | After an edit, the engine shall recalculate only the dirty set: the edited formulas plus the transitive closure of dependents.                                      | Must     | Implemented | GC-031         | Editing a cell with no dependents evaluates no other formula; the response lists edited cells plus recalculated cells whose value changed, and omits cells whose value is unchanged. |
| FR-021 | The engine shall evaluate dirty formulas in dependency order using an iterative Tarjan SCC pass.                                                                    | Must     | Implemented | GC-031         | A diamond (`B=A`, `C=A`, `D=B+C`) evaluates D once, after B and C; a 100,000-long chain recalculates without stack overflow.                                                         |
| FR-022 | Cells participating in a cycle (SCC of size > 1, or a self-reference, including through a range) shall evaluate to `#CYCLE!`, and recover when the cycle is broken. | Must     | Implemented | GC-031         | `A1=B1`, `B1=A1` both show `#CYCLE!`; `A1=SUM(A1:A3)` shows `#CYCLE!`; replacing B1 with a constant restores correct values; `IFERROR` downstream can contain the cycle error.       |
| FR-023 | Incremental recalculation shall produce exactly the same values as a full recalculation.                                                                            | Must     | Implemented | GC-032         | The randomized test runs 25 seeds of random edit sequences; after each step every cell equals a freshly built engine's value.                                                        |
| FR-024 | Cross-sheet references shall resolve by sheet id; formulas naming a not-yet-existing sheet shall bind when that sheet is added.                                     | Must     | Implemented | GC-031, GC-041 | `=Sheet2!A1` evaluates to `#REF!` until Sheet2 is added, then recalculates to the correct value; replacing the waiting formula stops the wait.                                       |
